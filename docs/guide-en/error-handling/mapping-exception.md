# Error Handling — MappingException

All code generated by kmap uses a single exception hierarchy: `com.sahsenvar.kmapper.MappingException`. Your feature layer converts these exceptions into your own domain errors — you never end up with a direct dependency on library types.

## Hierarchy

```kotlin
sealed class MappingException(message: String, cause: Throwable? = null)
    : RuntimeException(message, cause) {

    class RequiredFieldMissing(val field: String)
        : MappingException("Required field missing: $field")

    class TypeConversionFailed(val from: String, val to: String, cause: Throwable)
        : MappingException("Cannot convert $from -> $to", cause)

    class UnknownEnumValue(val enum: String, val value: Any)
        : MappingException("Unknown wire value '$value' for enum $enum")
}
```

### RequiredFieldMissing

If a nullable source field is mapped to a non-null target field and the value is `null`, the generated null-check throws:

```kotlin
// source: String?  →  target: String (non-null)
id = id ?: throw MappingException.RequiredFieldMissing("id")
```

If you provide a default value with `@MapDefaultValue`, that default expression is used instead of this exception. See [Null-Safety](../basic-usage/null-safety.md).

### TypeConversionFailed

If a converter (`MapTypeConverter`) throws an exception at runtime, the generated code wraps it in `TypeConversionFailed`. The raw platform exception never leaks:

```kotlin
// generated (conceptual):
startsAt = convertOrFail("String", "Instant") {
    IsoStringToInstantConverter.convertToNonNull(startsAt)
}
// If an invalid value like "abc" arrives:
// TypeConversionFailed(from="String", to="Instant", cause=DateTimeParseException)
```

The `cause` field carries the original exception; you can use it for logging.

### UnknownEnumValue

When the wire source sends a value that is not present in the enum definition, the `MappableEnum` forward path throws:

```kotlin
// "UNKNOWN_STATUS" arrived from the wire, but this wireValue doesn't exist in OrderStatus:
MappingException.UnknownEnumValue(enum = "OrderStatus", value = "UNKNOWN_STATUS")
```

See [MappableEnum](../enum/mappable-enum.md).

## Converting to a Domain Error

Write a `Throwable.toX()` extension in your feature layer to translate `MappingException` into your own hierarchy. Use a `when` block to handle all branches of the sealed hierarchy:

```kotlin
// feature/order/data/mapper/OrderMapper.kt
fun Throwable.toOrderError(): OrderError = when (this) {
    is MappingException.RequiredFieldMissing ->
        OrderError.DataCorruption("Required field missing: $field")
    is MappingException.TypeConversionFailed ->
        OrderError.DataCorruption("Conversion failed: $from → $to", cause)
    is MappingException.UnknownEnumValue ->
        OrderError.InvalidStatus("Unknown status value: $value")
    is RemoteError.Timeout ->
        OrderError.NetworkTimeout
    else ->
        OrderError.Unknown(message, this)
}
```

Call it inside the `catch` block in your repository layer:

```kotlin
override fun getOrder(id: String): Flow<Order> = flow {
    val dto = remoteDataSource.fetchOrder(id)
    emit(dto.toOrder())           // the generated mapper runs inside toOrder()
}.catch { exception ->
    throw exception.toOrderError()
}
```

## Compile-Time Safety Guarantees

The majority of `MappingException`s are prevented **at compile time**:

| Situation | Behavior |
|---|---|
| Required converter is in neither the global list nor the field annotation | **Compile error** |
| Enum does not implement `MappableEnum` and has no `@UseMapTypeConverter` | **Compile error** |
| Unconditional mapping cycle (A→B→A, all non-null) | **Compile error** |
| Nullable → non-null with no `@MapDefaultValue` | Generated `RequiredFieldMissing` (runtime) |
| Unknown wire enum value | Generated `UnknownEnumValue` (runtime) |
| Converter throws at runtime | Generated `TypeConversionFailed` (runtime) |

### Unconditional Cycle — Compile Error

The processor analyzes the `@MapTo`/`@MapFrom` type graph. If every edge in a cycle passes through a non-null, non-collection field, the object cannot be constructed and a compile error is emitted:

```kotlin
// ERROR — guaranteed infinite cycle
@MapTo(BDomain::class) data class A(val b: B)
@MapTo(ADomain::class) data class B(val a: A)
// e: Mapping cycle detected: A -> B -> A. This would cause infinite construction at runtime.
//    Break the cycle with a nullable field, a collection, or @Ignore.
```

If the cycle passes through at least one nullable or collection field (a tree, an optional back-reference), it is allowed:

```kotlin
// OK — conditional; nullable parent
@MapTo(CategoryDomain::class)
data class Category(val parent: Category?)

// OK — conditional; collection
@MapTo(NodeDomain::class)
data class Node(val children: List<Node>)
```
